# SillyTavern 手动导演第一版功能说明

> 文档类型：功能说明。本文只定义第一版做什么、如何使用及验收标准，不包含界面设计、技术架构和实现方案。

## 1. 背景

SillyTavern 群聊中同时启用多个角色时，系统可能选择错误的角色回应，或让角色以旁观者、全知视角代写其他角色，破坏沉浸感。

第一版使用“手动导演”方式验证受控群聊流程：用户先通过 SillyTavern 原生群聊功能禁止成员自动发言，再手动指定本轮旁白、主要回应者和可选的第二回应者，插件负责按照确定顺序执行。

## 2. 功能目标

- 允许手动维护简要剧情流程和当前剧情节点。
- 允许发布玩家和所有角色都能看到的剧情旁白。
- 允许指定一名主要演员回应。
- 允许额外指定一名第二演员，在主要演员之后回应。
- 允许分别为两名演员提供不可见的本轮表演指令。
- 保证旁白和演员回复按顺序执行，不并发生成。
- 为以后接入 AI 导演保留统一的“本轮导演决定”输入形式。

## 3. 使用前提

- 用户已经打开一个 SillyTavern 群聊。
- 可能参与剧情的角色已经加入群聊。
- 群聊使用“手动”激活策略。
- 用户已通过 SillyTavern 原生群聊功能将群成员设为禁止自动发言；第一版插件不负责管理禁言状态。
- 群组生成模式建议使用“交换角色卡”。
- SillyTavern 已连接可正常生成回复的模型。

## 4. 一轮互动流程

1. 玩家发送一条消息或做出一个动作。
2. SillyTavern 根据用户已有的群聊禁言设置保持无自动回应，插件进入“等待导演决定”状态。
3. 用户查看当前剧情节点，并按需调整本轮节点信息。
4. 用户可填写一段公开旁白。
5. 用户选择主要演员，并可填写该演员的本轮表演指令。
6. 用户可选择第二演员，并可填写该演员的本轮表演指令。
7. 用户确认执行本轮。
8. 如果填写了旁白，插件先将旁白作为剧情旁白发布到聊天中。
9. 插件向主要演员注入其本轮指令，并触发主要演员生成回复。
10. 主要演员完成后，插件清除其临时指令。
11. 如果选择了第二演员，插件再注入第二演员的本轮指令并触发回复。
12. 第二演员完成后，插件清除其临时指令，本轮结束。

## 5. 本轮导演决定

第一版由用户手动填写以下内容：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 当前剧情节点 | 是 | 当前场景正在进行的剧情位置，由插件保存 |
| 节点说明 | 否 | 当前节点的目标、已发生事件或注意事项 |
| 公开旁白 | 否 | 发布到聊天中，玩家和后续角色都能看到 |
| 主要演员 | 否 | 本轮首先发言的角色；允许只有旁白而没有演员回复 |
| 主要演员指令 | 否 | 仅用于主要演员本次生成，不显示在聊天中 |
| 第二演员 | 否 | 在主要演员完成后发言；不能与主要演员相同 |
| 第二演员指令 | 否 | 仅用于第二演员本次生成，不显示在聊天中 |

本轮决定的逻辑形式如下：

```json
{
  "currentNode": "客厅_识破暗号",
  "nodeSummary": "门外有人冒充王室卫队，王梦捷已经察觉异常。",
  "narration": "门外再次响起三短一长的敲门声，节奏却有一处明显停顿。",
  "speakers": [
    {
      "character": "王梦捷",
      "instruction": "已经识破暗号，但暂时不要直接说出真相。"
    },
    {
      "character": "曲非烟",
      "instruction": "听完王梦捷后，如果察觉她在隐瞒，再简短追问。"
    }
  ]
}
```

## 6. 功能范围

### 6.1 剧情信息

- 保存一段简要剧情流程，供手动导演参考。
- 保存并展示当前剧情节点。
- 允许用户手动修改当前节点和节点说明。
- 第一版不自动判断或推进剧情节点。

### 6.2 公开旁白

- 允许本轮不发布旁白。
- 发布时可使用固定名称“剧情旁白”。
- 旁白写入群聊记录，并进入后续角色可见的聊天上下文。
- 旁白本身不自动触发任何角色回应。

### 6.3 演员选择

- 从当前群成员中选择演员。
- 一轮最多选择两名演员。
- 允许只选择一名演员。
- 允许只有旁白、不选择演员。
- 不允许同一角色同时成为主要演员和第二演员。

### 6.4 演员本轮指令

- 每名演员可以有独立的本轮指令。
- 指令不作为可见消息写入聊天。
- 指令只影响对应演员的本次生成。
- 一名演员生成结束或失败后，都必须清除其临时指令。
- 默认要求演员只描写自己的语言、动作、感受和内心，不代写玩家或其他角色。

### 6.5 顺序执行

- 公开旁白始终先于演员回复。
- 第二演员必须等待主要演员完全生成并写入聊天后才能开始。
- 第二演员能够读取主要演员刚刚生成的回复。
- 本轮执行期间不能重复提交另一轮导演决定。

### 6.6 执行状态与恢复

- 明确显示等待决定、发布旁白、主要演员生成、第二演员生成、完成和失败状态。
- 允许用户在开始生成前取消本轮。
- 生成失败时显示失败发生在哪一步。
- 主要演员失败时不自动继续触发第二演员。
- 失败后允许用户重新执行本轮。

## 7. 第一版不包含

- AI 自动判断应该由谁发言。
- AI 自动生成导演决定。
- 自动理解“她”“身后的女孩”等语义指代。
- 自动推进或跳转剧情节点。
- 根据剧本自动添加、移出或启用群成员。
- 自动或批量管理群成员的禁言状态。
- 超过两名演员连续发言。
- 两名演员并行生成。
- 自动概率插话。
- 完整剧本解析、分支图编辑或可视化流程设计。
- 对 SillyTavern 角色卡进行创建、修改或删除。

## 8. 异常与限制

- 当前不是群聊时，不允许执行导演流程。
- 目标演员已不在群聊时，不允许开始生成，并要求重新选择。
- SillyTavern 正在生成其他消息时，本轮保持等待，不发起并发生成。
- 用户切换群聊或聊天记录后，未开始的导演决定应失效，避免发送到错误会话。
- 页面关闭、刷新或模型请求中断时，不保证继续未完成的生成。
- 模型仍可能不完全遵守本轮指令；第一版只保证选择正确的角色和正确的执行顺序。

## 9. 验收标准

第一版满足以下条件即可认为功能成立：

1. 插件不修改 SillyTavern 原有的群成员禁言状态。
2. 用户可以查看和修改当前剧情节点。
3. 公开旁白会显示在聊天中，并位于演员回复之前。
4. 选择一名演员时，插件只触发该演员生成回复。
5. 选择两名演员时，两人严格按照指定顺序生成两条消息。
6. 第二演员生成时能够读取主要演员刚刚生成的内容。
7. 两名演员各自只收到自己的本轮隐藏指令。
8. 隐藏指令不会显示在聊天记录中，也不会残留到下一轮。
9. 重复点击执行不会造成重复消息或并发生成。
10. 任何一步失败后，不会错误触发后续演员，并且用户可以重新执行。

## 10. 后续讨论入口

完成第一版验证后，再通过头脑风暴逐项讨论：

- 手动导演界面的具体交互方式。
- 剧情流程和节点的数据结构。
- AI 导演如何读取剧情和聊天上下文。
- 自动选择演员和有限随机插话。
- 动态角色进场、退场与认知边界。
- 关键剧情由人工控制、普通回合由 AI 控制的混合模式。
